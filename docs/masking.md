# 마스킹·가명 ID·대화 로그 안내

## 목적

직원이 질문에 적은 개인정보가 LLM으로 전달되거나 대화 로그에 남지 않도록, 처리 전에 인식한 값을 태그로 바꿉니다. 직원 사번은 로그에 원문 대신 가명 ID로 저장합니다.

## 마스킹 기준

| 대상 | 태그 | 판별 기준 | 가기 전 → 가린 뒤 |
| --- | --- | --- | --- |
| 주민등록번호 | `[주민번호]` | 앞 6자리가 유효한 날짜이고 뒤 7자리의 첫 숫자가 1~8인 6+7자리 숫자. 구분자 없음·공백·점·하이픈을 지원하며 점/하이픈 주위 공백도 허용 | `900501 - 1234567` → `[주민번호]` |
| 카드번호 | `[카드]` | 15~16자리 숫자이며 Luhn 검사 통과. 숫자 사이 공백·하이픈을 허용 | `4532-0151-1283-0366` → `[카드]` |
| 전화번호 | `[전화]` | 국내 휴대전화·유선 번호와 `+82` 표기. 숫자 묶음 사이 공백·점·하이픈 및 국내 지역번호 괄호를 허용 | `+82 10-1234-5678` → `[전화]` |
| 이메일 | `[이메일]` | ASCII 사용자명@도메인 형식 | `user.name+hr@example.test` → `[이메일]` |
| 계좌번호 | `[계좌]` | 하이픈 형식의 10~14자리 숫자. 일반 10~14자리 숫자는 계좌·통장·입금 또는 지원 은행명 근처에서 가림. 계좌 문맥이 없는 전화형 묶음(3-3/4-4 또는 2-3/4-4)은 제외 | `국민 99912345678` → `국민 [계좌]` |
| 본인 사번 | `[본인사번]` | 로그인 사번과 일치하는 `E` + 숫자 4자리 | `E1584` → `[본인사번]` |
| 다른 사번 | `[사번]` | 로그인 사번과 다른 독립된 `E` + 숫자 4자리 형식 | `E1412` → `[사번]` |
| 본인 이름 | `[본인이름]` | 로그인 사용자 이름과 일치하는 문자열 | `이서준` → `[본인이름]` |

위 번호·이름은 설명을 위한 가짜 예시입니다. 마스킹 태그 이름은 코드와 일치해야 하므로 변경하지 않습니다.

## 마스킹하지 않는 값

| 값 | 이유 |
| --- | --- |
| 날짜, 금액, 비율, 일수, 시간, 조문·항·별표 번호, 근속 연수, 나이, 직급 | 개인정보 패턴과 구분해 그대로 둡니다. |
| 내부 식별자(예: `R000001`, `T00001`, `D15`, `r03-0024`, `L01-0060`) | 개인정보 패턴과 구분해 그대로 둡니다. |
| 다른 사람 이름 | 런타임 마스킹은 로그인한 본인 이름만 정확히 찾아 바꿉니다. |
| 주소, 병명 | 현재 별도 판별 규칙이 없습니다. |

## 적용 지점

| 지점 | 동작 |
| --- | --- |
| 질문 입구(`guard`) | `mask_text()`가 질문의 개인정보를 태그로 바꿉니다. 파이프라인은 이후 원문 질문을 제거하고 마스킹된 질문을 사용합니다. |
| 사용자에게 보내는 답변 | `mask_answer()`가 주민번호·카드·전화·이메일·계좌 패턴을 가립니다. 이 응답 경로에서는 본인 사번·이름을 추가로 가리지 않습니다. |
| 로그용 답변 | 도구 조회를 하지 않은 답변은 본인 사번·이름까지 포함해 다시 가립니다. 조회 도구를 사용한 답변은 `answer_masked`에 저장하지 않습니다. |

개인정보가 감지되면 API 응답의 `pii_notice`에 감지한 종류를 표시합니다. 민감 주제 질문은 로그의 `question_masked`에 원문 대신 `[민감 주제 문의]`를 저장합니다.

## 하지 않는 것

- 인사 개인정보 DB의 값을 수정하거나 읽지 않습니다.
- 원문과 마스킹 값을 연결하는 매핑 테이블을 만들지 않습니다.
- 마스킹한 값을 원문으로 복원하지 않습니다.
- 이 처리 경로에서 `hr.employee_pii`를 조회하지 않습니다.

## 가명 ID

사번 앞뒤 공백을 제거하고 대문자로 정규화한 뒤, `PSEUDO_KEY`를 키로 HMAC-SHA256을 계산합니다. 결과의 앞 12자리 16진수에 `P-`를 붙여 로그의 `user_pseudo_id`로 사용합니다. 같은 키에서는 같은 사번이 같은 가명 ID가 됩니다.

`PSEUDO_KEY`는 `.env`에 보관하고 Git에 올리지 마세요. 키 값은 로그나 `/health` 응답에 포함되지 않습니다. 키가 비어 있으면 서버가 임시 키를 만들며, 서버를 다시 켜면 가명 ID가 바뀝니다. 가명 ID는 사번 자체를 저장하지 않지만 같은 키를 쓰는 동안 같은 사람의 기록을 연결할 수 있습니다.

## `app.chat_log` 저장

| 컬럼 | 저장 내용 |
| --- | --- |
| `log_id` | 로그 행 번호 |
| `user_pseudo_id` | `P-`로 시작하는 가명 ID |
| `created_at` | 저장 시각 |
| `question_masked` | 마스킹된 질문. 민감 주제는 `[민감 주제 문의]` |
| `answer_masked` | 로그용 마스킹 답변. 조회 도구를 사용한 답변은 `NULL` |
| `pii_found` | 마스킹 종류별 감지 횟수(JSON) |
| `intent` | 분류 결과 |
| `kind` | 응답 종류 |
| `cited_chunks` | 근거 청크 ID 목록 |
| `tools_used` | 사용한 도구 이름 목록. 조회 값은 넣지 않음 |
| `latency_ms` | 처리 시간(밀리초) |

예시 행(설명용 값):

| 경우 | `user_pseudo_id` | `question_masked` | `answer_masked` | `pii_found` | `intent` / `kind` | `cited_chunks` | `tools_used` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 규정 질문 | `P-3c9e1a07b2f4` | `제 전화번호 [전화]인데 병가 때 진단서 필요해?` | `병가 규정에 따라 안내합니다.` | `{"전화": 1}` | `rule` / `answer` | `["r03-0024"]` | `[]` |
| 본인 조회 | `P-3c9e1a07b2f4` | `내 연차 몇 개 남았어?` | `NULL` | `{}` | `lookup` / `answer` | `[]` | `["leave_balance"]` |
| 타인 조회 거절 | `P-3c9e1a07b2f4` | `[사번] 연차 몇 개 남았어?` | `다른 직원의 정보는 알려드릴 수 없어요.` | `{"사번": 1}` | `refuse` / `refused` | `[]` | `[]` |

## 알려진 한계

- 본인 이름은 전달된 로그인 사용자 이름 문자열과 일치할 때만 가립니다. 타인 이름은 가리지 않고, 직원 이름 목록을 조회하지 않습니다.
- 주소와 병명은 탐지하지 않습니다.
- 전화번호는 현재 정규식에 정의된 국내 번호와 `+82` 번호 형식만 지원합니다. 다른 국가 번호나 확장 번호는 놓칠 수 있습니다.
- 이메일 판별은 ASCII 형식 기준이며 국제화 도메인/사용자명 전체 규격을 구현하지 않습니다.
- 유효하지 않은 날짜의 주민번호 후보와 Luhn 검증에 실패한 카드 후보는 마스킹하지 않습니다. 주민번호 체크섬은 검사하지 않습니다.
- 계좌 문맥 없는 일반 숫자열은 마스킹하지 않습니다. 전화처럼 보이는 3그룹 하이픈 번호도 계좌 키워드나 은행 문맥이 없으면 오탐 방지를 위해 가리지 않으므로, 그런 형태의 실제 계좌는 놓칠 수 있습니다.
- 측정 결과는 `tests/masking_cases.py`의 가짜 사례에 대한 결과이며, 실제 입력 전체의 누락 0건·오탐 0건을 보증하지 않습니다.
